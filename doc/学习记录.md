#### git 操作顺序

0. 如果代码不是`git clone`下来的，需要先`git init`来创建仓库, `git remote add origin 地址`来关联远程仓库。
1. `git pull`来更新代码到最新状态(更改代码前的更新)
2. 编写代码
3. `git commit`保存代码到本地仓库
4. `git pull`查看远程仓库的版本与本地有有无冲突
5. `git push`上传到远程仓库

对于需要创建分支的情况：
1. `git checkout -b 分支名`创建分支
2. 修改代码
3. 先后使用`git checkout master ` `git log --oneline ` `git diff main 分支名 ` `git merge 分支名`切换回master并合并分支。
4. 后面commit和push相同

#### 总结

|命令|作业|使用时机|
|---|---|---|
|`git clone`|把远程仓库克隆到本地并创建本地仓库|刚开始在本地上着手处理此项目时|
|`git init`|创建新本地仓库|本地项目开始用git管理|
|`git pull`|更新代码，与远程仓库同步|开始工作前，push前|
|`git remote add origin 地址`|关联远程仓库|刚创立本地仓库，上网|
|`git commit`|保存代码到本地仓库|修改完代码后|
|`git push`|上传代码到远程仓库|最后的最后|
|`git checkout -b 分支名`|创建分支|写代码前|
|`git checkout master ` |切换回master分支|合并前|
|`git merge 分支名`|合并分支|确认无误，计划合并后|
|`git branch -d 分支名`|删除分支|不想要这个分支时|
|`git log --oneline` `git reset --hard HEAD~1`|回退，撤销上一次修改|版本回调时|

```bash
git add Core/Srd/main.c
git commit -m "将闪烁次数调整为5"
git checkout -b feature-blink
git checkout master
git log --oneline
git diff master feature-blink
git merge feature-blink
```

回退后，部分“学习记录”的内容丢失（最近一次改动是撰写“学习记录”）

因此，最好在新建的分支里面回退而非整个主干，不然可能出现意外。以及，撤回之前应该先确认好是否真的需要回退

#### 认识编译产物

按下F7，编译完成之后，出现了后缀为`.o`、`.axf`、`.hex`的一系列文件。经查找资料，总结他们的用途如下：

| 文件后缀 | 全称 | 是什么 | 什么时候用 |
|---|---|---|---|
| `.o` | Object File（目标文件） | 单个 `.c` 文件编译后的中间产物，里面是机器指令，但还缺地址信息 | 只能用于链接，不能直接烧芯片。`Objects` 文件夹里就能找到 `main.o`、`buzzer.o`、`led.o` 等 |
| `.axf` | ARM Executable File（含调试信息的可执行文件） | 链接后的完整程序，带有函数名、变量名等调试信息。Keil 调试时靠它绑定源码 | 调试时用（比如断点、变量查看）。烧写时也可，但芯片不需要保留调试信息 |
| `.hex` | Intel Hex File（十六进制烧录文件） | 就是 `.axf` 去掉调试信息后的纯烧写数据，可直接通过任何烧录器写入芯片 | 正式量产或脱离 Keil 烧录时用。Keil 的 `F8` 也是用这个文件 |

F7将会对于工程文件中的所有.c文件进行编译，不止main.c函数。编译后产出机器认识的二进制编码。

最终F8把.hex文件写入机器中

修改代码后，重新编译的仅仅是在电脑上执行。要想完成机器上的修改，必须重新F8把代码录入到机器内

#### 添加新组件

加入`user`新组件后，机器在执行后面的闪烁蜂鸣等程序之前会立即响三声，响的频率按照长 - 短 - 短进行。

#### 移除文件查看报错

移除hardware/inc 后产生了4个报错。移除移除 `hardware` Group 里的 `buzzer.c` 和 `led.c`也出现了大量的报错。

Include Paths 负责让编译器找到 `.h` 头文件，Group 里的 `.c` 负责提供函数实现，两者缺一不可。

#### 修改现象验证闭环

把 `DELAY_MS` 从 `250U` 改成 `500U`，重新编译下载，观察速度变化，并单独提交。修改之后，LED每轮频闪的频率明显变慢，时间边长。

#### 工具流配置

报错一：开始一直卡在一个加载页面，直接叉掉后显示 One or more Device Family Pack Devices are not present - would you like to choose another device?检查后发现自己之前漏装了keil的一些芯片支持包。通过回到“控制组软件”里面下载对应支持包解决

报错二：刚刚连接板子，初次编译后按F8报错：Error: Flash Download failed  -  Target DLL has been cancelled。解决方法：检查 Keil 调试器设置。工程打开状态下，点击菜单 Project → Options for Target...随后切换到 Debug 选项卡。右侧Use选择 ST-Link Debugger。随后点击F8，正常运行。
